Privacy & Security

Private by architecture, not just by policy.

Gratuvia is being built so the phone can remain the authoritative source for core work and earnings records rather than requiring every shift, tip slip, and payroll setting to pass through a company server.

Local-first records

Core earnings, schedules, payroll settings, OCR reviews, and tip-slip records are designed to work from local device storage without requiring a network connection.

Private on-device OCR

The current Android beta uses a private native OCR path with models bundled into the app. Recognition runs locally rather than uploading the tip slip to a cloud OCR service.

Encrypted structured data

Core structured app records are stored in a SQLCipher-protected SQLite database. The database key is generated on the device and kept in platform secure storage.

Originals stay originals

Gratuvia preserves the original selected or captured tip-slip image separately. OCR preprocessing can make temporary working images without rewriting the original evidence file.

Integrity checks

Original tip-slip files are hashed with SHA-256 so Gratuvia can verify that imported or restored records still match the expected bytes.

User-owned encrypted backups

Portable backups are designed to be encrypted on the device using AES-256-GCM before you save them. The recovery key is kept separate from the backup file.

What "local-first" means in Gratuvia

Local-first does not mean the app can never use the internet. It means the core record system does not need cloud processing to function. Tracking shifts, tips, wages, schedules, payroll settings, OCR reviews, and original tip-slip records is designed to remain usable from the device itself.

This also means you carry more control — and some responsibility. Device loss, deletion, or a lost backup recovery key can matter if your records exist only under your control. Gratuvia's backup tools are intended to give you a portable encrypted copy without requiring Prokvik to hold the plaintext contents.

OCR is assistive, not authoritative

Gratuvia's OCR pipeline is intentionally separated from the final earnings record. The OCR engine reads the image, the parser interprets likely fields, and you review the result. A bad OCR guess should not silently become an authoritative earnings entry.

Supported document templates can use targeted recognition passes to improve field association while preserving the untouched original image.

Cloud services are optional by design

Gratuvia may add optional sync, account, or backup services later. The architecture is intended to synchronize from a local source of truth rather than make a remote database mandatory for core tracking.

If a future feature changes what information is transmitted to Prokvik or a service provider, we will update the Privacy Policy and the relevant in-app disclosures before relying on that feature.

Claims we intentionally do not make

No application can promise perfect security. Gratuvia does not describe itself as "unhackable," and we will not use labels such as "zero-knowledge" or "end-to-end encrypted" unless the implemented system and a security review support those exact claims.

Questions or security reports

If you believe you found a security or privacy issue, contact admin@prokvik.com. Please avoid sending sensitive user data unless it is necessary to explain the issue.
